# ダンジョン自動生成基盤

このフォルダーは、`rot.js`を使ってダンジョンの構造を生成・検査する独立モジュールです。
現時点では`index.html`、`maps.js`、ゲーム中のマップ移動処理には接続していません。

## ファイル

- `dungeonProfiles.js`: 標準設定、名前付きプロファイルの検証・ID参照・入出力API
- `dungeonSavedProfiles.js`: エディターで保存するプロファイル一覧。ゲーム側も同じファイルを読む
- `dungeonGenerator.js`: 生成、経路解析、役割・設置候補の割り当て、検査、再試行
- `dungeonGenerator.test.js`: Node.jsで実行できる基盤テスト
- `dungeonRooms.js`: 部屋の角丸化、出入口の保護、実際の床範囲と輪郭の記録
- `dungeonRooms.test.js`: 角丸形状・出入口と接続・小さい部屋・設置候補・保存設定のテスト
- `dungeonWallSpace.js`: 壁の高さと最上段の上の余白を確保する行の挿入・座標の更新
- `dungeonWallSpace.test.js`: 壁の高さ・余白・接続・扉・配置・シード再現性のテスト
- `dungeonPlacementSafety.js`: 宝箱と固定イベントを障害物として扱う通行・調査位置の検査
- `dungeonPlacementSafety.test.js`: 狭い道・複数の障害物・調査不能・実際の生成結果の回帰テスト
- `dungeonCorridors.js`: 道の抽出、幅の変化、途中の膨らみ、角を丸める追加掘削
- `dungeonCorridors.test.js`: 道の接続・部屋と外周の保護・スケールと部屋面積の影響・生成テスト
- `dungeonTiles.js`: 用途別の重ねタイル設定、旧設定の互換読込、地形分類、描画
- `dungeonTiles.test.js`: 用途の分類・描画順・画像寸法・設定保存・地形不変のテスト
- `dungeonEditorSettings.js`: エディターのタイル・宝箱・敵設定ウィンドウ
- `dungeonEditorProfiles.js`: プロファイル切替、新規作成・参照コピー、編集状態の保持、ファイル保存、JSON入出力
- `dungeonProfiles.test.js`: 保存形式・ID参照・再読込・設定補正の往復テスト
- `dungeonEditorProfiles.browser.test.js`: ヘッドレスChromeでの保存・上書き・削除・JSON読込テスト
- `../dungeon-editor.html`: ブラウザで生成・編集結果を確認する独立ツール

## 現在できること

- `ROT.Map.Digger`による部屋と通路の生成
- 部屋ごとの確率で角をタイル単位に丸め、四角い部屋と角丸の部屋を混在させる
- 数値または文字列シードによる再現
- マップ端から入口部屋へ接続する、分岐のない専用通路を生成
- 入口から遠く、専用通路を作れる部屋を出口部屋に選び、マップ端まで出口通路を生成
- ゴールは出口部屋内ではなく、出口通路の外周終端に配置
- 入口から出口までの主経路と、主経路外の部屋を解析
- 部屋へ入口、出口、分岐、宝物、任意の休憩、イベントの役割を割り当て
- 敵、罠、装飾の配置候補を重複なしで生成
- 選択した敵プールから各敵候補へ敵IDを割り当て
- 選択した宝箱抽選表から各宝箱へ中身を割り当て
- 道の床、部屋の床、道の壁、部屋の壁、余白を別々の重ねタイルで描画
- 指定した高さ分の壁と、その最上段の上の余白1マスを生成時に確保する
- スケール、接続する部屋の面積、シード乱数に応じて道ごとの幅を変え、途中の膨らみや一部の角の丸みを生成
- 入口周辺の安全距離を確保
- 必須イベントの占有範囲と調査位置候補を確保
- 宝箱・固定イベントを配置した後も、出口と全ての残りの床、各オブジェクトの調査位置へ到達できることを検査
- 部屋数、主経路長、枝部屋数、床面積率、必須配置数を検査
- 不合格時に別の派生シードで再生成し、通常は合格するまで続ける
- 開発時だけ明示的な試行上限を設定できる
- 開発確認用のASCIIプレビューを生成

生成処理中は`ROT.RNG`を一時的に使用しますが、処理終了後に元のシードと内部状態を復元します。

## 標準設定

### 規模と危険度

- `scale`: `1`～`10`。標準は`3`。値に応じてマップの縦横、部屋数、最低主経路長、入口通路長、配置する魔物数が増減する。
- `danger`: `1`～`10`。標準は`3`。値が大きいほど魔物候補数と、枝道抽選で罠を含む確率が増える。罠の増加倍率は魔物数より強めに設定している。追加の宝箱率は危険度1の20%から危険度10の70%まで直線的に増える。
- `scale: 3`かつ`danger: 3`では、サイズ・魔物数・罠の補正倍率がそれぞれ1倍になる。
- `scale`は部屋自体の大きさではなく、マップ全体の広さと収容する部屋数を変える。

標準プロファイルの基本マップサイズは、規模1で`42 x 28`、規模3で`60 x 40`、規模10で`102 x 68`となる。壁と余白の間隔が足りない場合は、生成結果へ必要な行を追加するため実際の縦幅は増える。実際の部屋構成や配置数は範囲内で抽選される。

- サイズ: `60 x 40`
- 部屋: `6～12室`
- 部屋サイズ: `4～9 x 4～7`
- 通路長: `2～8`
- 主経路: `30マス以上`
- 主経路外の部屋: `2室以上`
- 宝物候補: 最低1個確定、その後は対象枝道ごとの追加抽選
- 敵候補: `4～8`
- 罠候補: 枝道ごとの抽選結果による
- 再試行上限: なし（成功するまで再生成）
- 入口から敵・罠までの最低距離: `8マス`
- 入口専用通路: `3～18マス`、上下左右いずれかの外周から接続
- 入口通路の曲がり: 標準45%で発生、最大2回
- 出口専用通路: `3～18マス`、上下左右いずれかの外周へ接続
- 出口通路の曲がり: 標準45%で発生、最大2回
- 空の枝道の内容: 何もなし、罠、終点に宝箱、罠と宝箱の4種類。危険度に応じて確率を調整する。
- 追加の宝箱率: `20% + (危険度 - 1) * 50% / 9`。危険度1で20%、3で約31.1%、5で約42.2%、10で70%。宝箱のみと罠＋宝箱の合計。
- 宝箱位置: 確定分はランダムな部屋、追加分は枝道の終点部屋。それぞれ角または角付近を優先。
- 休憩地点: `0`

標準の`dugPercentage`は`0.20`です。`60 x 40`で`0.28～0.35`を指定すると、現在の部屋サイズでは部屋数が13室以上になりやすいため、実測に合わせています。

休憩地点は場所だけを表す汎用枠です。回復効果はこの生成基盤では決めません。標準では生成されず、個別ダンジョンで`restCount`を設定した場合だけ候補が作られます。

宝箱率は罠の倍率による正規化と切り離して補正する。「何もなし」と「宝箱」、「罠」と「罠と宝箱」の間で確率を移すため、罠の出現率は既存の危険度補正から変わらない。独自の抽選表で重み0にした結果は新しく有効化せず、同じ罠の有無の範囲で移せる分だけ宝箱率を補正する。

最初の宝箱は追加抽選とは別に配置する。確定するのは個数だけで、配置する部屋はシード乱数で選び、部屋内の位置も従来通り角寄せ付きのランダム配置にする。固定座標や固定の部屋にはしない。`roomRoles.treasureCount`の標準は`[1, 1]`。古いプロファイルに`[0, 0]`が残っていても、生成時に最低1個へ補正する。保存ファイルそのものは書き換えない。追加抽選を無効にした場合も確定分は配置する。確定分を安全に置けない地形は不採用として再生成する。

確定分には`guaranteed: true`、枝道抽選で増えた分には`guaranteed: false`を付ける。確定の宝箱を置いた部屋は追加抽選の対象から除き、残りの対象枝道をそれぞれ1回抽選する。追加が外れてもほかの枝道の抽選は続く。エディターには確定数・追加数・追加の宝箱率を表示する。

## Node.jsでの使用例

```js
const ROT = require("../../rot.js-master/dist/rot.js");
const DungeonGenerator = require("./dungeonGenerator.js");
const DungeonProfiles = require("./dungeonProfiles.js");

const generator = DungeonGenerator.create(ROT);
const result = generator.generate(DungeonProfiles.standard, { seed: "sample-seed" });

console.log(result.metrics);
console.log(DungeonGenerator.toAscii(result));
```

テストはプロジェクト直下から次のコマンドで実行します。

```powershell
node map/dungeon/dungeonGenerator.test.js
node map/dungeon/dungeonProfiles.test.js
node map/dungeon/dungeonTiles.test.js
node map/dungeon/dungeonCorridors.test.js
node map/dungeon/dungeonRooms.test.js
node map/dungeon/dungeonWallSpace.test.js
node map/dungeon/dungeonPlacementSafety.test.js
node map/dungeon/dungeonEditorProfiles.browser.test.js
```

ブラウザーテストは実際の保存ファイルを書き換えず、ファイル選択APIをメモリ内の保存先へ差し替える。Chromeの場所は必要なら環境変数`CHROME_PATH`で指定する。一時的なChromeプロファイルはテスト終了時に削除する。

## タイルの用途と重ね合わせ

タイル設定は次の5用途に分かれる。いずれの用途も、床・壁タグや`passable`による候補の制限はしない。

- `path`: 道の床。部屋以外の移動可能セル。入口・出口通路と、部屋の外の扉セルも含む。
- `room`: 部屋の床。生成された部屋の内側の移動可能セル。
- `pathWall`: 道の床の真上にある通行不可セル。
- `roomWall`: 部屋の床の真上にある通行不可セル。
- `margin`: その他の通行不可セルと、プレビューのマップ外の余白。

`wallHeight`は壁の高さ（マス数）。標準は1、0なら壁表示なし。床の真上へ指定数だけ進み、通行不可セルを道壁または部屋壁にする。壁の最上段の1マス上は必ず余白にする。壁を短くしたり省略したりして間隔を合わせることはしない。左右・下・斜めには伸ばさない。マップ外は引き続き余白として描画する。

生成時は部屋・道・入口・出口の形を作り終えた後、壁用の間隔を確保する。上下に分かれた床の間に通行不可セルが`wallHeight + 1`マス以上残るよう、不足する行だけを挿入する。マップ上端側も壁と余白を確保するが、外周へつながる入口・出口の床はそのまま外周につながる。追加行の床は元から上下に直接つながっていた床の間だけに補うため、別の部屋や通路を勝手につなげない。高さ0なら行を追加しない。

行を追加した後、扉・部屋の範囲と輪郭・道の形・入口・出口の座標と経路を更新し、その地形で主経路、距離、配置候補、採用条件を計算する。床・扉を壁や余白で覆わず、プロファイルの壁の高さも変更しない。生成結果の`height`と`config.height`は追加後の実際の縦幅。`wallSpacing.baseHeight`と`wallSpacing.rows`には追加前の高さと行の対応を保持する。エディターには実際のサイズと壁用の追加行数を表示する。

入口・出口通路の長さ範囲は、壁用の間隔を確保する前の生成に適用する。行を追加した場合は`baseLength`に元の長さを残し、`length`と`path`は追加後の実際の長さと経路に更新する。

各用途はタイルIDの配列で保存し、配列の先頭から下の層、上の層の順で重ねる。例えば次の設定では草地の上へ木を重ねて道壁と余白を描き、部屋壁は別画像にする。

```js
tiles: {
  path: ["road"],
  room: ["grass"],
  pathWall: ["grass", "tree"],
  roomWall: ["caveWallHorizontal01"],
  margin: ["grass", "tree"],
  wallHeight: 3,
}
```

設定ウィンドウは用途タブ、重ね順と合成プレビュー、全タイルのパレットで構成する。層を選択してパレットから置き換え、`＋`で重ねる層を追加できる。層は上下移動・削除可能。未選択の層が残る間は適用できない。`[]`ならその用途の画像を描かず、地形確認用の背景色だけを表示する。

描画は全セルの下層を描き終えてから上層へ進み、同じ層では奥の行から手前の行へ進む。タイル定義の`drawWidth`、`drawHeight`、描画オフセット、`bottomCenter`アンカーを参照するため、木などの大きい画像を1マスへ押し縮めない。マップ外にも余白の重ねタイルを繰り返し描く。

タイル画像や重ね順だけを変えても、生成した`cells`の地形・配置・乱数抽選は変えない。ただし`wallHeight`の変更は、必要な間隔の確保により生成結果の縦幅・座標・配置へ影響する。ゲーム側へ接続する際は、地形は`cells`、宝箱と固定イベントを含めた通行判定は`navigationCells`を参照し、選択画像の`passable`に置き換えない。

旧`floorTileId`だけの設定は道・部屋へ、旧`wallTileId`だけの設定は道壁・部屋壁・余白へ引き継ぐ。旧共通`wall`の重ねタイルは道壁・部屋壁の両方へ引き継ぐ。新設定でも`floorTileId`、`wallTileId`、`wall`は互換用として残すが、用途別配列がある場合はそちらを優先する。旧設定で高さがない場合は1マス。

## 部屋の角丸化

`rot.js`で長方形の部屋を作った後、入口・出口通路を選ぶ前に部屋の角を整える。`generator.roomShape`の標準設定は`{ roundingChance: 0.55, maxCornerRadius: 3 }`。部屋ごとに抽選し、選ばれた部屋の角を円弧に近い階段状に切り取る。最大半径は部屋の短辺にも制限されるため、小さい部屋ほど控えめな丸みになる。確率または最大半径を0にすれば角丸化を止められる。

- 既存の扉と、境界で実際につながっている通路から部屋中央への床を保護する。部屋の角に入口がある場合も通行を残す。
- 部屋中央と中央の床幅を残し、小さい部屋を空洞化しない。
- 角丸化した後に入口・出口・主経路・配置を決める。宝箱は切り取った元の角ではなく、残っている床の角付近を優先する。イベントの占有範囲も実際の床で確認する。
- 通路を広げる処理が削った角を埋め戻さないよう、部屋の元の範囲と周囲を保護する。
- `room.area`は角丸化後の実際の床面積。部屋の幅と高さは外接する長方形のサイズとして残す。
- エディターの部屋枠は`outlineEdges`に沿って描き、実際の床形状と一致させる。生成結果に角丸の部屋数も表示する。

角丸化は専用のシード乱数系列を使い、設定はプロファイルへ保存される。

## 宝箱と固定イベントの通行確認

宝箱と固定イベントは通行を遮るオブジェクトとして扱う。配置候補ごとに既に置いた全オブジェクトと新しい候補の占有範囲を通行不可とし、入口から全ての残りの床と出口へ到達できるか検査する。また、各オブジェクトに少なくとも1つ、入口から到達できる上下左右の調査マスが必要。複数の宝箱を組み合わせた場合の通行遮断や、ほかのオブジェクトに囲まれて調べられなくなる配置も採用しない。

宝箱の角寄せは安全な候補の中で行う。優先する角付近が全て危険なら、ほかの床へ候補を広げる。必要数を安全に置けなかった生成結果は、従来通り不採用として再生成する。配置終了時にも全体を再検査し、`blocking: true`と到達可能な`approach`を各オブジェクトへ記録する。

`cells`は見た目に使用する元の床・壁・扉を維持する。別の`navigationCells`は宝箱と固定イベントの占有範囲を`1`にした実移動用の配列。主経路はこの配列を使って配置後に引き直し、プレビューの主経路線が宝箱を横切らないようにする。魔物、罠、休憩候補、装飾候補は現時点では固定障害物に数えない。ゲーム本体へ接続する際も、オブジェクトを開けた後に通れるかどうかなどは別途決める。

## 道幅の変化

`rot.js`の生成した部屋・道と入口／出口通路を基準に、部屋以外の床を分岐点間の道として抽出する。道ごとの目標幅はスケール、両端側に接続する部屋の面積、独立したシード乱数から決める。部屋面積は幅への偏りであり、次の部屋が小さくても乱数で道が太くなる場合がある。

- 始端と終端の目標幅の間を徐々に変化させ、一定確率で道中へ山型の膨らみを足す。
- 一部の曲がり角は曲線に沿う追加掘削で、タイル単位の段階的な丸みを付ける。
- 元の床・扉を消さない追加掘削方式。部屋の内側と外周1マスを保護し、入口・出口の場所とマップ外周の開口も維持する。
- 別の道の床や追加掘削部分へ勝手に接続しないよう確認し、追加する床は既存の床に接している場合だけ採用する。
- 形の変更後に主経路・設置候補・採用条件を再計算する。

`generator.corridorShape`の標準値は`{ enabled: true, minWidth: 1, maxWidth: 5, bulgeChance: 0.65, roundingChance: 0.55 }`。`maxWidth`は道中心線に使う目標幅の上限で、曲がり角や合流部全体の外形を切り詰める上限ではない。`enabled: false`で追加掘削を止められる。これらの値もプロファイルに保存される。

エディターの生成結果に実測の道幅と角を丸めた箇所数を表示する。道の変化に独立した乱数系列を使い、同じ設定とシードなら同じ結果を再現する。

## プロファイルの保存とゲーム側の指定

上部のプロファイル一覧から、map-editorと同じように直接切り替える。`新規作成`、`JSON読込`、`保存・管理`も上部に配置する。

- `新規作成`は、初期設定から新しく作る方法と、一覧から選んだ設定を参照コピーする方法を選べる。`新規作成1`、`dungeon_1`から、既存名・IDと被らない番号を自動で付ける。
- 保存済みプロファイルと、編集中の新規プロファイルを一覧で区別する。新規作成・JSON読込だけでは保存ファイルを書き換えない。
- 切替時に破棄確認は出さず、各プロファイルの未保存設定と確認用シード・表示切替をメモリ内に個別保持する。戻るとその編集状態を復元する。
- 未保存設定の保持は同じ編集画面を開いている間だけ。画面を閉じる際は、現在開いていないものも含めて未保存編集があれば警告する。
- `保存・管理`からIDと名前を付けて新規保存・上書き・削除できる。標準プロファイルは上書き・削除不可。未保存の新規プロファイルの削除は、その編集状態だけを破棄する。

- 保存先は`map/dungeon/dungeonSavedProfiles.js`。ブラウザーのlocalStorageには保存しない。
- 最初のファイル保存時に、Chrome/Edgeのファイル選択でこの保存先ファイルを指定する。同じ編集画面では選択した保存先を再利用する。
- 書き込みが完了した場合だけ保存済みにする。上書き・削除は確認を取る。
- 保存前にファイルを読み直し、別のプロファイルを上書きで消さないように更新する。
- 保存済みの設定は上部のプロファイル選択で読み込める。再度エディターを開いた場合も、保存ファイルから一覧を復元する。
- `JSON書出し`は編集中の1プロファイルを共有・バックアップ用に出力する。`JSON読込`は未保存の編集状態として読み込む。ゲーム側の一覧に追加するにはファイルに保存する。
- 規模、危険度、入口・出口の方向、タイル、宝箱の抽選表、魔物の抽選表を含め、生成に使う補正前の設定を保存する。`result.config`は補正済みのため保存しない。
- 確認用シードと表示切替は`preview`へ分けて保存する。ゲーム側の設定取得にはこれらを含めない。

ゲームへ接続するときは、上記の順でスクリプトを読み込み、プロファイルIDを指定するだけで生成設定を取得できる。

```js
const generator = HEALER_DUNGEON_GENERATOR.create(ROT);
const config = HEALER_DUNGEON_PROFILES.get("kuraku_forest");
const dungeon = generator.generate(config); // シード省略時は毎回新しく生成
```

`kuraku_forest`は保存時に付けるIDの例。未知のIDはエラーにし、標準設定へ黙って置き換えない。`get()`はコピーを返すため、地域ごとの一時的な変更も保存済みの元データに影響しない。

Node.jsでは`require("./dungeonProfiles.js").get("kuraku_forest")`で同じ設定を取得できる。現時点ではゲーム本体へのマップ接続は引き続き行っていない。

## 生成結果の主要項目

- `cells`: 行優先の一次元配列。`0=床`、`1=壁`、`2=扉`
- `navigationCells`: `cells`に宝箱・固定イベントの占有範囲を加えた実移動用配列。オブジェクトの位置は`1`
- `tileRegions`: 行優先で各セルの描画用途を保持。`path`、`room`、`pathWall`、`roomWall`、`margin`
- `rooms`: 部屋の範囲、中心、扉、役割、入口からの距離。`shape`、`cornerRadius`、`roundedCorners`、`floorCells`、`outlineEdges`で実際の形状も保持
- `corridors`: 通路の始点、終点、長さ
- `corridorShapes`: 道ごとの中心線、接続側の部屋ID、目標幅・実測幅、追加床、膨らみ、丸みを付けた角
- `wallSpacing`: 壁用の間隔を確保する前の高さ、追加後の高さ、追加行数、元の行から新しい行への対応
- `entrance`、`exit`: 入口と出口の座標
- `entranceApproach`: 外周から入口部屋までの専用通路、接続方向、扉
- `exitApproach`: 出口部屋から外周のゴールまでの専用通路、退出方向、扉
- `mainPath`: 入口から出口までの4方向経路
- `branchRoomIds`: 主経路外の部屋ID
- `branchRoutes`: 配置を決めるために使う、オブジェクト配置前の地形上の枝道経路。実移動時は`navigationCells`で経路を求める
- `placements`: イベント、宝物、休憩、敵、罠、装飾の候補
- `placements.treasure[].approach`と`placements.mandatoryEvents[].approach`: オブジェクト配置後にも到達可能な調査マス
- `placements.treasure[].contents`: その宝箱に抽選された内容
- `placements.treasure[].guaranteed`: 固定数の確定配置か、枝道抽選による追加配置かを区別する
- `placements.enemies[].enemyId`: その敵候補に抽選された敵ID
- `config.tiles`: 選択した床・壁タイルID
- `reservations`: 重要物が使用している予約マス
- `metrics`: 部屋数、経路長、床面積率、配置数など
- `validation`: 採用可否、エラー、警告
- `attempts`: 採用までに試した各シードの結果

生成結果のセル配列は中立データで、選択した画像タイルIDは`config.tiles`に保持します。現在の`HEALER_TILE_MAPS`形式への変換は、実際にゲームへ接続するときにテーマ別の変換処理として追加します。

## 必須イベントの例

```js
const profile = {
  ...HEALER_DUNGEON_PROFILES.standard,
  id: "forest_ruins_1f",
  mandatoryEvents: [
    {
      id: "stone_monument",
      type: "story",
      required: true,
      preferBranch: true,
      minEntranceDistance: 15,
      footprint: { width: 2, height: 2 },
      data: { storyId: "forest_ruins_monument" },
    },
  ],
};
```

イベントが条件を満たす部屋へ置けなかった場合、その生成結果は不採用になります。

地域ごとに入口から進む方向を固定する場合は、プロファイルを次のように上書きします。`down`はマップ上端から下向きに進む入口です。

```js
const southboundRegion = {
  ...HEALER_DUNGEON_PROFILES.standard,
  entranceApproach: {
    ...HEALER_DUNGEON_PROFILES.standard.entranceApproach,
    startDirections: ["down"],
  },
};
```

複数方向を許可する場合は`["down", "right"]`のように指定できます。入口通路の長さは`minLength`と`maxLength`、曲がる確率は`turnChance`、最大曲がり回数は`maxTurns`で設定します。

通常は成功するまで再生成します。設定値の検証中だけ停止させたい場合は、プロファイルの`retryLimit`または生成時の`maxAttempts`へ正の整数を指定できます。上限に達した場合も固定テンプレートは要求せず、`ok: false`と`reason: "attempt_limit_exhausted"`を返します。
