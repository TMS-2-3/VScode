# Map Folder

> 現在の正式データは、タイル定義が map/tile.js、マップ定義が map/maps.js です。

## 概要

このフォルダーは、マップ担当用の作業場所です。  
通常のマップ制作では、この `map` フォルダー内だけを触ってください。

- マップデータの正式な管理先: `map/maps.js`
- タイル画像の正式な管理先: `map/img_tile/`
- エディター: `map/map-editor.html`
- ダンジョン生成・編集: `map/dungeon-editor.html`
- 未接続のダンジョン自動生成基盤: `map/dungeon/`

`Desktop\map` や `Downloads` にある一時ファイルは、正式データとしては扱いません。  
また、通常のマップ制作では `world/tileMapSystem.js` を編集しないでください。そこは共通の仕組み側です。

## 共同制作者向けルール

- 作業は基本的に `map` フォルダー内で完結させる
- マップ定義の最終反映先は `map/maps.js`
- タイル画像は `map/img_tile/...` に置く
- 共有メモや README は、文字化けが不安なときは英語でもよい
- 日本語の表示名を使う場合は、保存後に文字化けしていないか確認する

## 現在の作業フロー

1. `map-editor.html` で配置や下書きを作る
2. 必要に応じてブラウザ側の一時保存や作業記録保存を使う
3. 最終的な内容はエディターから書き出して `map/maps.js` に反映する
4. `maps.js` 更新後に、エディターやプレビューを再読込して確認する

ブラウザ側の保存は下書き用です。  
正式データは必ず `maps.js` に反映してください。

## エディターの使い方

### 基本

- `新規作成`: 新しいマップの下書きを作る
- `反映`: 幅、高さ、タイルサイズなどの入力内容を現在のマップに反映する
- `作業記録JSON保存`: 作業記録を JSON で保存する
- `作業記録JSON読込`: 保存した作業記録を読み込む
- `JS書き出し`: `maps.js` に入れるためのマップ定義を書き出す
- `maps再読込`: `maps.js` を再読み込みして、反映後の状態を確認する

### 補足

- エディター上の `新規作成` は、ブラウザ上の未登録マップを作るだけです
- `新規作成` しただけでは `maps.js` には保存されません
- 画面内の状態表示で、現在のマップが `maps.js` の既存マップか、未登録の新規マップかを確認できます

## マップ定義の基本

`window.HEALER_TILE_MAPS` に各マップを定義します。

```js
exampleMap: {
  id: "exampleMap",
  name: "サンプルマップ",
  tileSize: 48, // 互換用。実際のタイルサイズは tile.js の HEALER_TILE_SIZE を使う
  width: 15,
  height: 8,
  defaultTile: "grass",
  marginTiles: {
    ground: "test_grass",
    terrain: null,
    object: null,
    event: null,
  },
  layers: [
    { id: "ground", name: "地面", tiles: [] },
    { id: "terrain", name: "地形", tiles: [] },
    { id: "object", name: "配置物", tiles: [] },
    { id: "event", name: "イベント", tiles: [] },
  ],
  events: [],
}
```

### レイヤーの役割

- `ground`: 草、土、道、水、石などの地面
- `terrain`: 崖、森の壁、通行不可地形など
- `object`: 木、岩、建物、看板、飾りなど
- `event`: イベント用の配置情報

### 直線コピー

- イベントのパレットに `直線コピー（下方向／上方向／左方向／右方向）` がある
- 設置マスの地面・地形・配置物などのレイヤーを、矢印の方向へ1マスずつ繰り返す。マップ外の余白にも延長する
- コピー元は設置マスに保存されているタイル。別の直線コピーから再コピーはしない
- コピー先はレイヤー一式を参照するため、コピー元にない配置物などはコピー先に表示されない
- マップ内はタイルの通行判定も反映する。マップ外は描画のみで、通行やイベント発動はできない
- `map.events` の移動イベント・施設設定などは複製せず、それぞれの元の座標で動作する
- 複数のコピーが交差する場合は、元の配置の上から下・左から右の順で後にあるコピーを優先する。ただしコピー元のマス自体は上書きしない
- イベントの矢印はエディターだけに表示する。エディターでは選択中のタイルやコピーイベントの有無によらず余白を常に3マス分プレビューし、ゲームではカメラに必要な範囲まで描画する
- 保存されるのは元のタイルとコピーイベントだけ。元を変更すれば延長先にも反映し、イベントを消せば元のマップに戻る
- 共通処理は `world/tileMapSystem.js`。変更の確認は `node world/tileMapSystem.test.js` で行える

## タイル定義の基本

`window.HEALER_TILE_DEFS` に各タイルを定義します。

```js
grass: {
  id: "grass",
  name: "草地",
  image: "map/img_tile/base_seamless/grass_plain_01.png",
  passable: true,
  tags: ["ground"],
}
```

### 主な項目

- `id`: タイルID
- `name`: 表示名
- `image`: 画像パス
- `passable`: 通行可能かどうか
- `tags`: 用途分類

## タイル方針

- タイルサイズはゲーム全体で共通。`tile.js` の `window.HEALER_TILE_SIZE` を変更すると、ゲーム側・map-editor側の基準サイズが変わる
- 各マップの `tileSize` は互換用に残しているだけで、個別設定としては使わない
- `defaultTile` はマップ内の標準地面用。マップ外の余白埋めは `marginTiles` で別に指定する
- map-editorではパレットで地面タイルを選び、上部の「標準地面」セルを押すと `defaultTile` が変わる
- 草、土、道、水、石などの繰り返し地形は、できるだけ低コントラストのシームレスタイルを使う
- 花、濃い草、ひび割れ石、かぶせ用タイルなどの強い見た目は、変化用・強調用として使う
- 建物や配置物は `object` レイヤーへ置く
- 森の壁や崖のような通行不可地形は `terrain` レイヤーへ置く

## メモ

- ダンジョン編集は`dungeon-editor.html`。名前付き生成設定の保存先は`dungeon/dungeonSavedProfiles.js`で、`HEALER_DUNGEON_PROFILES.get("ID")`からゲーム側も同じ設定を取得できる。操作・読込順・テストは`dungeon/README.md`を参照。ゲーム本体のマップにはまだ接続していない。
- 文字化けが起きやすい共有文は、無理に日本語へ統一せず英語を使っても大丈夫です
- マップ担当以外が読むことを考えて、ID・ファイル名・レイヤー名はなるべく一貫させてください
